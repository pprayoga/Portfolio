Diary Agent

A personal knowledge system I built and run in production — it turns my daily journal into structured recaps and a clean to-do list, and lets an AI assistant answer questions over my notes and paper library.

LLM pipeline MCP FastAPI Streamlit SQLite / FTS5 AWS Cloudflare

Overview

Diary Agent is a system I use every day. Each night it reads my journal entry and produces two things: a recap of any meetings, and a deduplicated to-do list pulled from what I actually committed to. Separately, it keeps a library of research papers I've read — auto-tagged and searchable — and exposes the whole knowledge base to an AI assistant so I can ask questions in plain language instead of digging through files.

How it works

The nightly job runs a two-stage LLM pipeline. Meeting detection and to-do extraction run in parallel, then a second pass deduplicates the to-dos so the same task never lands twice. The extraction prompt is a four-branch decision tree that knows when it runs — about 1 AM the next day — so phrases like "tonight" resolve to the past and casual or aspirational mentions don't turn into false to-dos.

Getting that reliable took real evaluation: I benchmarked candidate models and prompts over repeated runs (N=3) to separate genuine improvements from the model's run-to-run variance, and landed on a configuration scoring 23/25 on a hand-built test suite. That "measure it three times before you trust it" discipline came straight from years of field commissioning.

The paper library adds automatic tagging, title-normalized deduplication, and full-text search over SQLite (FTS5). All of it — diary and papers — is served through a Model Context Protocol (MCP) server, so an AI client can run natural-language queries like "papers on animal intelligence from June" and get accurate, grounded retrieval. I validated the retrieval against a seeded corpus, including deliberate over- and under-inclusion traps.

Running it in production

It's deployed on AWS EC2 with a FastAPI backend and a Streamlit UI, reached through a Cloudflare Tunnel with Cloudflare Access handling auth, and driven by a cron job for the nightly recap. I profiled memory to find the true baseline, separated app load from dev-tooling overhead, and right-sized the instance (t3.medium → t3.micro) — cutting monthly cost roughly 4× without touching the workload.
